SCIP Indexing Upgrade Plan (Protobuf Parsing + Deterministic Identity)

Overview
This plan upgrades SCIP ingestion to parse index.scip via protobuf, fixes
range/role correctness, and standardizes scip-python invocation with
--project-name CodeIntel (no project-version or project-namespace). It also
adds richer SCIP data capture (relationships, diagnostics, external symbols)
and hardens the build flow against stale reuse. The end state maintains a
perpetual index.scip that is incrementally updated per module using hash-based
change detection and fully regenerated when missing. Protobuf bindings are
generated by a dedicated Hamilton target and used downstream via artifact paths.

Goals
- Parse index.scip with protobuf as the source of truth.
- Use a stable project identity: --project-name CodeIntel.
- Fix occurrence range parsing and preserve full symbol_roles.
- Unify SCIP parsing logic across ingestion paths to avoid drift.
- Capture richer SCIP metadata to improve navigation, analysis, and LLM context.
- Make skip/reuse deterministic via input hashes, not file existence alone.
- Maintain a perpetual index.scip with module-level incremental updates.
- Remove index.json from the core pipeline (protobuf is canonical).

Non-Goals
- Multi-tenant namespacing (no --project-namespace).
- Project versioning in SCIP symbol identity.
- JSON export as a required artifact.

Design Decisions (Accepted)
- scip-python CLI: always pass --project-name CodeIntel.
- No --project-version or --project-namespace.
- Parse index.scip via protobuf (google protobuf Python runtime).
- Drop index.json artifacts in the main pipeline.
- Protobuf bindings are generated via a DAG-coupled codegen target.
- Codegen uses grpcio-tools (python -m grpc_tools.protoc).

Phase 5 - Perpetual Index and Incremental Module Updates
1) Recover or reintroduce prior incremental SCIP logic
   - Search the repo history and archived modules for earlier SCIP incremental
     indexing and merging logic.
   - If found, re-home it under the current ingestion pipeline and align it
     with Hamilton nodes and current schemas.

2) Compute module deltas using hash-based change detection
   - Use ChangeDetectionPort to compute added/modified/deleted modules and a
     state_hash.
   - Persist module state in a durable table (core.scip_module_state) as the
     source-of-truth. The shard manifest remains a cache/inspection artifact
     that can be regenerated from the table when missing or inconsistent.
   - Add schema core.scip_module_state with:
     (rel_path, content_hash, options_hash, tool_version, shard_path, updated_at).
   - Include scip options hash and scip-python version in the module-level
     hash to avoid stale shard reuse.

3) Run per-module indexing for changed modules
   - For each changed module, run scip-python with --target-only=module_path.
   - Store per-module .scip files in a stable, collision-safe layout:
     - {scip_dir}/shards/<hash_prefix>/<content_hash>__<rel_path_sanitized>.scip
   - Maintain a shard manifest mapping:
     - rel_path -> content_hash, options_hash, tool_version, shard_path
   - Remove or mark per-module artifacts for deleted modules.

4) Update the perpetual index.scip
   - If index.scip is missing or invalid, perform a full repo index to seed it.
   - Otherwise, load index.scip via protobuf and apply a document-level update
     keyed by Document.relative_path:
     - Replace documents for modified/added modules.
     - Remove documents for deleted modules.
     - Merge external_symbols and symbol_information deterministically:
       - Deduplicate by full symbol string.
       - Prefer the newest shard by updated_at when both candidates are equally
         informative.
       - Prefer the row that adds information (non-empty documentation,
         signature, display_name) over less complete rows to avoid regressions.
       - For external symbols, prefer the most complete package triple
         (manager+name+version), then newest shard.
   - Normalize output ordering for determinism (documents sorted by relative_path).
   - Write the updated index.scip atomically (temp file + rename).

5) DAG-coupled orchestration
   - Add Hamilton nodes for:
     - change detection
     - per-module indexing
     - index.scip update/merge
     - scip_proto codegen (as an upstream dependency)
   - Ensure the scip target input hash includes the module state hash and
     scip options, so incremental runs are deterministic.

6) Failure and rebuild strategy
   - If any per-module index fails or merge validation fails, fall back to a
     full scip-python index for correctness.
   - If shards are missing or inconsistent, rebuild the canonical index from
     shards; if that fails, run a full repo index.
   - Always emit a consistent index.scip; no JSON artifact is required.

Appendix A - scip_proto Target Sketch (Hamilton)
This sketch shows the concrete node signatures and decorators for a DAG-coupled
protobuf codegen target. It is intended to be copied into
src/codeintel/build/hamilton/native/ingestion/scip_proto.py and adjusted to
match final naming.

Codegen tool choice (recommended)
- Use grpcio-tools since it is already in pyproject.toml.
- Configure ToolsConfig.protoc_bin to the venv python (default "python").
- Invoke: python -m grpc_tools.protoc --python_out <out_dir> <proto_path>

```python
from __future__ import annotations

import asyncio
from dataclasses import dataclass
from pathlib import Path

from hamilton.function_modifiers import source, value

from codeintel.build.hamilton.boundary_types import MaterializationMetadata
from codeintel.build.hamilton.env import BuildEnv
from codeintel.build.hamilton.materializers import FileArtifactSaver
from codeintel.build.hamilton.naming import materialize_node
from codeintel.build.hamilton.native.executor import NativeTargetExecutor
from codeintel.build.hamilton.native.materialization_records import (
    record_from_file_artifact_materializations,
)
from codeintel.build.hamilton.native.target_decorators import (
    TargetSpecDescriptor,
    codeintel_target,
)
from codeintel.build.hamilton.run_records import TargetRunRecord
from codeintel.build.hamilton.save_to import SaveToObjectMetadataDecorator
from codeintel.build.hamilton.tagging import tag_compute, tag_tool
from codeintel.build.hashing import InputHashOptions
from codeintel.build.resources import TOOL_EXECUTION, TargetResources
from codeintel.core.hashing import file_hash
from codeintel.core.tools import ToolName
from codeintel.ingestion.engine.infrastructure import ToolExecutionError, ToolRunOptions
from codeintel.build.hamilton.dag_catalog import DagCatalog

SCIP_PROTO_TARGET = "scip_proto"
SCIP_PROTO_ARTIFACT = "scip_pb2"


@dataclass(frozen=True)
class ScipProtoRunResult:
    success: bool
    output_path: Path | None = None
    error: str | None = None


def _proto_path(repo_root: Path) -> Path:
    return repo_root / "src" / "codeintel" / "ingestion" / "scip" / "proto" / "scip.proto"


def _proto_out_dir(env: BuildEnv) -> Path:
    return env.paths.scip_dir / "proto"


@tag_tool(domain="ingestion", target=SCIP_PROTO_TARGET)
def t__scip_proto__run(env: BuildEnv, catalog: DagCatalog) -> ScipProtoRunResult:
    proto_path = _proto_path(env.snapshot.repo_root)
    out_dir = _proto_out_dir(env)
    output_path = out_dir / "scip_pb2.py"
    hash_options = InputHashOptions(file_state_hash=file_hash(proto_path))
    executor = NativeTargetExecutor.for_target(
        env,
        catalog,
        SCIP_PROTO_TARGET,
        hash_options=hash_options,
    )
    if executor.should_skip():
        return ScipProtoRunResult(success=True, output_path=output_path)
    args = [
        "-m",
        "grpc_tools.protoc",
        "--python_out",
        str(out_dir),
        str(proto_path),
    ]
    try:
        result = asyncio.run(
            env.providers.tool_runner.run_async(
                ToolName.PROTOC,
                args,
                options=ToolRunOptions(
                    cwd=env.snapshot.repo_root,
                    output_path=output_path,
                    timeout_s=env.providers.tool_runner.tools_config.default_timeout_s,
                ),
            )
        )
        if not result.ok:
            raise ToolExecutionError(result)
    except Exception as exc:
        return ScipProtoRunResult(success=False, error=str(exc))
    return ScipProtoRunResult(success=True, output_path=output_path)


@SaveToObjectMetadataDecorator(
    [FileArtifactSaver],
    output_name_=materialize_node("artifact.scip_pb2"),
    env=source("env"),
    catalog=source("catalog"),
    target_name=value(SCIP_PROTO_TARGET),
    artifact_name=value(SCIP_PROTO_ARTIFACT),
    path_template=value("{scip_dir}/proto/scip_pb2.py"),
)
@tag_compute(domain="ingestion", target=SCIP_PROTO_TARGET, target_="scip__proto_artifact")
def scip__proto_artifact(t__scip_proto__run: ScipProtoRunResult) -> Path | None:
    if not t__scip_proto__run.success:
        return None
    return t__scip_proto__run.output_path


@tag_compute(domain="ingestion", target=SCIP_PROTO_TARGET)
def scip__proto_module_path(
    env: BuildEnv,
    t__scip_proto__run: ScipProtoRunResult,
) -> Path | None:
    if not t__scip_proto__run.success:
        return None
    return t__scip_proto__run.output_path


@tag_compute(domain="ingestion", target=SCIP_PROTO_TARGET)
def scip__proto_materializations(
    m__artifact__scip_pb2: MaterializationMetadata,
) -> dict[str, MaterializationMetadata]:
    return {SCIP_PROTO_ARTIFACT: m__artifact__scip_pb2}


@codeintel_target(
    domain="ingestion",
    target=SCIP_PROTO_TARGET,
    spec=TargetSpecDescriptor(
        resources=TargetResources(
            tracker=True,
            tools=("protoc",),
        ),
        execution=TOOL_EXECUTION,
    ),
)
def t__scip_proto(
    env: BuildEnv,
    catalog: DagCatalog,
    scip__proto_materializations: dict[str, MaterializationMetadata],
) -> TargetRunRecord:
    return record_from_file_artifact_materializations(
        env=env,
        catalog=catalog,
        target_name=SCIP_PROTO_TARGET,
        materializations=scip__proto_materializations,
    )
```
